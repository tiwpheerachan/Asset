## 1. ระบบนี้คืออะไร

ONE Asset คือระบบทะเบียนทรัพย์สินถาวร ใช้ขึ้นทะเบียน ติดตาม คิดค่าเสื่อมราคา และจำหน่ายทรัพย์สิน โดยเชื่อมกับ:
- **One OA** — รับคำขอซื้อที่อนุมัติแล้วมาขึ้นทะเบียน
- **ONEBOOK (บัญชี)** — ดึงบิลทรัพย์สินที่ลงบัญชีแล้วมาสร้างทรัพย์สิน และส่งค่าเสื่อมรายเดือนกลับไปลงสมุดรายวัน

หน้าจอทุกหน้ารองรับ 3 ภาษา (ไทย/English/中文) สลับได้ที่มุมขวาบน ข้อมูลหลัก (บริษัท หมวดหมู่ สถานที่ ฯลฯ) เก็บชื่อทั้ง 3 ภาษา

## 2. เข้าใช้งานและบทบาท/สิทธิ์

### บทบาท (Role)
| บทบาท | คำอธิบาย |
|---|---|
| **ACCOUNTANT** เจ้าหน้าที่บัญชีทรัพย์สิน | ทำงานประจำวัน: สร้าง/แก้ฉบับร่าง นำเข้า คำนวณค่าเสื่อม อัปโหลดเอกสาร |
| **MANAGER** หัวหน้าบัญชี | สิทธิ์ของ ACCOUNTANT + อนุมัติทรัพย์สิน ปิดงวดค่าเสื่อม แก้หมวดหมู่/ผังบัญชี |
| **ADMIN** ผู้ดูแลระบบ | จัดการผู้ใช้ ข้อมูลหลัก การตั้งค่า การเชื่อมต่อ (ไม่ยุ่งงานบัญชีทรัพย์สินโดยตรง) |
| **AUDITOR** ผู้ตรวจสอบ/ผู้ดู | ดูได้ทุกอย่าง + ส่งออกรายงาน แต่แก้ไขไม่ได้ |

### ตารางสิทธิ์ (RBAC)
| สิทธิ์ | ACCOUNTANT | MANAGER | ADMIN | AUDITOR |
|---|:--:|:--:|:--:|:--:|
| ดูทรัพย์สิน | ✓ | ✓ | ✓ | ✓ |
| สร้างทรัพย์สิน / แก้ฉบับร่าง | ✓ | ✓ | – | – |
| อนุมัติทรัพย์สิน | – | ✓ | – | – |
| คำนวณค่าเสื่อม | ✓ | ✓ | – | – |
| ปิดงวดค่าเสื่อม | – | ✓ | – | – |
| แก้หมวดหมู่ / แก้ Mapping บัญชี | – | ✓ | (หมวดหมู่เท่านั้น) | – |
| นำเข้าจาก OA/บัญชี | ✓ | ✓ | – | – |
| อัปโหลดเอกสาร | ✓ | ✓ | – | – |

## 3. ภาพรวมเมนูทั้งหมด

แถบเมนูซ้ายแบ่ง 4 กลุ่ม (พับเก็บได้ด้วยไอคอนมุมบน):

**ภาพรวม**
- แดชบอร์ด (`/`) — KPI + กราฟ + งานที่ต้องทำ
- กระบวนการ (`/flow`) — ภาพรวมสถานะและเส้นทางทรัพย์สิน

**งานทรัพย์สิน**
- นำเข้าจาก OA (`/oa-import`) — คิวนำเข้าจาก OA และจากบัญชี
- ทะเบียนทรัพย์สิน (`/assets`) — รายการทรัพย์สินทั้งหมด
- สถานที่ (`/locations`) — ผังสถานที่ บริษัท→สาขา→อาคาร→ชั้น→ห้อง
- ตรวจนับทรัพย์สิน (`/verify`) — แคมเปญตรวจนับ
- เอกสาร (`/documents`) — คลังเอกสารแนบทั้งหมด

**บัญชี**
- หมวดหมู่ (`/categories`) — หมวดหมู่ + ค่าเริ่มต้นค่าเสื่อม + ผังบัญชี
- ค่าเสื่อมราคา (`/depreciation`) — คำนวณ/ปิดงวด/ส่งเข้าบัญชี
- รายงาน (`/reports`) — รายงานมาตรฐาน 6 แบบ
- คลังความรู้ (`/knowledge`) — บทความบัญชี/ภาษีสร้างด้วย AI

**การควบคุม**
- บันทึกการตรวจสอบ (`/audit`) — Audit log (แก้/ลบไม่ได้)
- ตั้งค่า (`/settings`) — ข้อมูลหลัก เลขเอกสาร การเชื่อมต่อ สิทธิ์

แถบบนทุกหน้า: ช่องค้นหา (รหัส/ชื่อ/Serial/เลขใบแจ้งหนี้/เลขที่ OA), งวดปัจจุบัน, สลับระบบ (ไป OA/ONEBOOK), สลับภาษา, เมนูผู้ใช้ (รีเซ็ตข้อมูลทดลอง, ออกจากระบบ) และปุ่ม "คู่มือการใช้งาน →" (`/help`)

## 4. กระแสงานหลัก

เส้นทางเต็มของทรัพย์สิน 1 ชิ้น:

```
แหล่งที่มา ──> นำเข้า/ตรวจสอบ ──> สร้างทรัพย์สิน(DRAFT) ──> เปิดใช้งาน(ACTIVE) ──> คิดค่าเสื่อมรายเดือน ──> จำหน่าย/เก็บถาวร
   │                                                                              │
 OA อนุมัติ / บิล ONEBOOK                                           ส่งค่าเสื่อมกลับ ONEBOOK
```

ขั้นตอนบนหน้า "นำเข้าจาก OA" (ribbon):
`OA APPROVED → IMPORT / SYNC → ASSET CANDIDATE → CLASSIFY → CREATE ASSET (DRAFT) → REVIEW → ACTIVATE`

**สรุปทีละขั้น**
1. **นำเข้า** — กด "ดึงข้อมูลจาก OA" (คำขอซื้อที่อนุมัติ) หรือ "นำเข้าจากบัญชี" (บิลที่ลงบัญชีแล้วใน ONEBOOK) → เข้าคิว
2. **ตรวจสอบ/จำแนก** — เปิดรายการในคิว กด "เริ่มตรวจสอบ" ระบบตรวจรายการซ้ำ 4 จุด เลือกหมวดหมู่ (ค่าเสื่อม/บัญชีเติมให้อัตโนมัติ)
3. **สร้างทรัพย์สิน** — เลือกแยกรายชิ้นหรือกลุ่มเดียว กด "สร้างทรัพย์สิน" → ได้ทรัพย์สินสถานะ **ฉบับร่าง (DRAFT)**
4. **เปิดใช้งาน** — เปิดรายละเอียด ตั้งข้อมูลให้ครบ (โดยเฉพาะ **วันที่พร้อมใช้งาน** และสถานที่) → "ส่งขออนุมัติ" → หัวหน้าบัญชี "อนุมัติและเปิดใช้งาน" → **ACTIVE**
5. **คิดค่าเสื่อม** — เมนูค่าเสื่อมราคา สร้างรอบรายเดือน → คำนวณ → ยืนยันตรวจแล้ว → ปิดงวด
6. **ส่งเข้าบัญชี** — หลังปิดงวด กด "ส่งเข้าบัญชี ONEBOOK" เพื่อลงสมุดรายวันค่าเสื่อม (เฉพาะทรัพย์สินที่มาจาก ONEBOOK)
7. **สิ้นอายุ** — โอนย้าย ซ่อมบำรุง หรือจำหน่าย (ขาย/ทำลาย/สูญหาย/บริจาค/ตัดจำหน่าย) ระบบคิดกำไร/ขาดทุนจาก NBV ให้

## 5. รายละเอียดแต่ละหน้า

### 5.1 แดชบอร์ด (`/`)
การ์ด KPI 8 ใบ (คลิกลัดไปหน้ากรองได้): ทรัพย์สินทั้งหมด, ราคาทุนรวม, ค่าเสื่อมสะสม, มูลค่าตามบัญชี (NBV), ทรัพย์สินใหม่เดือนนี้, ยังไม่มีรูป, ยังไม่มีหมวดหมู่, รอเปิดใช้งาน
กราฟ: แนวโน้มค่าเสื่อมรายเดือน, มูลค่า/จำนวนตามหมวดหมู่, มูลค่าตามบริษัท/สาขา/แผนก
"รายการที่ต้องดำเนินการ": OA รอตรวจสอบ, ไม่ระบุสถานที่, ไม่มีนโยบายค่าเสื่อม, ขาดเอกสาร, จะครบอายุภายใน 6 เดือน · "กิจกรรมล่าสุด" 6 รายการ

### 5.2 กระบวนการ (`/flow`)
ภาพรวมเรียลไทม์: KPI 4 ใบ, เส้นทางกระบวนการแบบคลิกได้, แนวโน้มมูลค่า (จริง+คาดการณ์ เลือกช่วง 6 เดือน/1 ปี/3 ปี/ทั้งหมด), สถานะค่าเสื่อม, สัดส่วนตามหมวดหมู่, การแจ้งเตือนสำคัญ (ใกล้หมดอายุค่าเสื่อม ≤6 เดือน, ประกันใกล้หมด ≤90 วัน, ขาดเอกสาร, ไม่มีสถานที่) และงานตกค้าง

### 5.3 นำเข้าจาก OA (`/oa-import`)
- ปุ่ม **ดึงข้อมูลจาก OA** (คำขอซื้อที่อนุมัติ) และ **นำเข้าจากบัญชี** (บิล ONEBOOK)
- แท็บ **คิวรายการนำเข้า** (กรองตามสถานะ) และ **Mapping ฟิลด์** (แก้การจับคู่ฟิลด์ OA→Asset, เฉพาะ ADMIN)
- คลิกแถว → หน้าต่างตรวจสอบ (ReviewDrawer):
  - **ข้อมูลต้นทางจาก OA** — เลขที่ OA/PO, ผู้ขาย, จำนวน, ยอดเงิน, ไฟล์แนบ
  - **ตรวจสอบรายการซ้ำ** 4 จุด: เลขที่ OA, เลขที่ใบแจ้งหนี้, Serial Number, อ้างอิงรายการรอลงทะเบียน (ขึ้น "ผ่าน" หรือ "พบรายการซ้ำ")
  - **รายการทรัพย์สินที่จะสร้าง** — เลือกหมวดหมู่ (บังคับ) → ค่าเสื่อม/บัญชี/ราคาทุนต่อหน่วยเติมให้เอง
  - **แยกเป็นทรัพย์สินรายชิ้น** — ถ้าจำนวน >1 เลือกแยกเป็นรายชิ้น (คนละรหัส/Serial/QR) หรือรวมเป็นกลุ่มเดียว พร้อมพรีวิวรหัสที่จะได้
  - ปุ่มตามสถานะ: **เริ่มตรวจสอบ** → **ยืนยันพร้อมสร้าง** หรือ **สร้างทรัพย์สิน (n)** (ข้ามขั้น) · **ปฏิเสธ** (ต้องมีเหตุผล)
- เตือน "ต่ำกว่าเกณฑ์เข้าทรัพย์สิน" ถ้าราคาต่อหน่วย < 3,000 บาท (ควรลงเป็นค่าใช้จ่าย)

### 5.4 ทะเบียนทรัพย์สิน (`/assets`)
- ปุ่ม: **เพิ่มทรัพย์สิน**, **นำเข้า Excel ข้อมูลเดิม** (`/assets/import`), **ส่งออก Excel**
- ตัวกรอง: ค้นหา, หมวดหมู่, สาขา, แผนก, สถานะ, ตัวกรองเพิ่มเติม (บริษัท/ศูนย์ต้นทุน/สถานที่/หมวดย่อย/ช่วงวันที่) และชิป "ข้อมูลไม่ครบ" (ไม่มีรูป/ขาดเอกสาร/ไม่ระบุสถานที่/ไม่มีหมวดหมู่/ไม่มีนโยบายค่าเสื่อม)
- เลือกคอลัมน์ได้ (21 คอลัมน์) มีแถวยอดรวม และแบ่งหน้า 25/50/100
- คลิกแถว → QuickView แล้วกด "เปิดรายละเอียด"

**นำเข้าทรัพย์สินเดิม (`/assets/import`)**: วิซาร์ด 3 ขั้น อัปโหลด → ตรวจสอบ/พรีวิว → บันทึก มี "ดาวน์โหลด Template" ตรวจ error (ไม่มีรหัส/ไม่พบหมวดย่อย/ราคาทุนผิด/รหัสซ้ำ) ทรัพย์สินที่นำเข้าจะเป็นสถานะ **ACTIVE** พร้อมตัวเลข legacy

### 5.5 รายละเอียดทรัพย์สิน (`/assets/[id]`)
หัวเรื่อง: ชื่อ + ป้ายสถานะ, ปุ่ม **แก้ไข**, **พิมพ์ป้าย** (QR), และปุ่มเปลี่ยนสถานะ
การ์ด 4 ใบ: ราคาทุนรวม, ค่าเสื่อมสะสม(งวดปัจจุบัน), NBV, อายุคงเหลือ

**แท็บ**
- **ภาพรวม** — รูป (อัปโหลดได้), QR, ข้อมูลทั่วไป, โครงสร้างองค์กร, อ้างอิงการจัดซื้อ, และ "ชุด/กลุ่มที่แยกมา" (ลิงก์พี่น้องที่แยกจาก OA เดียวกัน)
- **บัญชี** — ตารางราคาทุน (ทุน+เพิ่ม−สะสม=NBV), นโยบายค่าเสื่อม (วิธี/อายุ/ซาก/proration/เริ่มคิด), การผูกบัญชี 3 บัญชี, และตารางเทียบ Legacy (ถ้ามี)
- **ค่าเสื่อมราคา** — ตารางค่าเสื่อมรายเดือนทั้งอายุ เลือกปี + ส่งออก มีป้าย LOCKED/งวดปัจจุบัน
- **สถานที่** — ไทม์ไลน์ลำดับสถานที่
- **ซ่อมบำรุง** — บันทึกซ่อม + "เพิ่มบันทึกซ่อมบำรุง" (ซ่อมแซม/บำรุงเชิงป้องกัน/ตรวจเช็ค/สอบเทียบ/อื่นๆ)
- **เอกสาร** — อัปโหลดเอกสารแนบ (เตือนถ้าขาด INVOICE/รูป)
- **ประวัติ** — สายการอนุมัติ + Audit ของทรัพย์สินชิ้นนี้

**ปุ่มเปลี่ยนสถานะ** (ขึ้นตามสถานะและสิทธิ์)
- DRAFT → **ส่งขออนุมัติ** (ต้องไม่มีข้อมูลค้าง) → PENDING_REVIEW
- PENDING_REVIEW → **อนุมัติและเปิดใช้งาน** → ACTIVE / **ส่งกลับเป็นฉบับร่าง**
- ACTIVE → **ปรับเป็นไม่ใช้งาน**, **ขอจำหน่าย**, **ย้าย/โอนย้าย**
- DISPOSAL_PENDING → **ยืนยันการจำหน่าย** (เปิด DisposalModal: เลือกประเภท ขาย/เศษซาก/สูญหาย/ชำรุด/บริจาค/ตัดจำหน่าย, ใส่รายรับ ระบบคิด NBV + กำไร/ขาดทุน) / **ยกเลิกคำขอ**
- INACTIVE/DISPOSED → **เปิดใช้งานอีกครั้ง**, **เก็บถาวร**

> การแก้ฟิลด์ที่กระทบบัญชี (ราคาทุน/อายุ/นโยบาย/วันที่) หลังเปิดใช้งานแล้ว ต้องเป็น MANAGER และต้องใส่เหตุผล

### 5.6 สถานที่ (`/locations`)
ผังต้นไม้ บริษัท→สาขา→อาคาร→ชั้น→ห้อง (ซ้อนได้ไม่จำกัดชั้นผ่าน "สถานที่แม่") มีถัง "ทรัพย์สินที่ยังไม่ระบุสถานที่" · เพิ่ม/แก้สถานที่ได้ (ADMIN)

### 5.7 ตรวจนับทรัพย์สิน (`/verify`)
สร้างแคมเปญตรวจนับ (ต้องมีสิทธิ์คำนวณค่าเสื่อม) ภายในแคมเปญบันทึกผลรายชิ้น: พบถูกที่ / พบผิดที่ / ชำรุด / ไม่พบ มีการ์ดสรุปและปุ่ม "ปิดแคมเปญ" (ล็อกผล)

### 5.8 เอกสาร (`/documents`)
คลังเอกสารแนบทั้งหมด กรองตามประเภท/ระบบต้นทาง (OA/Fixed Asset/Legacy)/ค้นหา (การอัปโหลดทำที่หน้ารายละเอียดทรัพย์สิน)

### 5.9 หมวดหมู่ (`/categories`)
ผัง 2 ชั้น (หมวดหมู่/หมวดย่อย) แต่ละหมวดกำหนด: หน่วยนับ, อายุใช้งานเริ่มต้น (ปี), มูลค่าซากเริ่มต้น, วิธีคิดค่าเสื่อม และ **การผูกบัญชี** 3 บัญชี (สินทรัพย์/ค่าเสื่อม/ค่าเสื่อมสะสม) มีตารางอ้างอิงอัตราค่าเสื่อมตามกฎหมายและเกณฑ์ตั้งทรัพย์สิน · แก้หมวดได้ (MANAGER/ADMIN) แก้ผังบัญชีได้ (MANAGER)

### 5.10 ค่าเสื่อมราคา (`/depreciation`)
3 แท็บ:
- **รอบคำนวณรายเดือน** — ป้ายสถานะงวด (ฉบับร่าง→คำนวณแล้ว→ตรวจแล้ว→ปิดงวดแล้ว→ลงบัญชีแล้ว) ปุ่ม **สร้างรอบใหม่** (เปิดได้เมื่องวดล่าสุดปิด/ลงบัญชีแล้ว), ต่อแถว: **คำนวณ**, **ยืนยันตรวจแล้ว** (MANAGER, ติดถ้ามี error), **ปิดงวด** (MANAGER), **ตรวจสอบ**
- **ตรวจสอบก่อนปิดงวด** — เลือกงวด ดูการ์ดสรุป (จำนวน/ค่าเสื่อมงวด/สะสม/NBV/ข้อผิดพลาด/ไม่มีนโยบาย/วันพร้อมใช้ผิด), แยกตามหมวดหมู่ + รายชิ้น, **ส่งออก Excel**, และ **ส่งเข้าบัญชี ONEBOOK** (เปิดเมื่องวด = ปิดงวดแล้ว และมีทรัพย์สินที่มาจาก ONEBOOK)
- **นโยบายค่าเสื่อม** — เพิ่ม/แก้นโยบาย (MANAGER): ชื่อ, หมวด, วิธี (ปัจจุบันมีเส้นตรง), อายุปี, ซาก, เริ่มคิด, proration, การปัดเศษ, วันมีผล

### 5.11 รายงาน (`/reports`)
6 รายงาน: ทะเบียนทรัพย์สิน, สรุปตามหมวดหมู่, ตารางค่าเสื่อม (ตามปีบัญชี), ตามสถานที่, ข้อมูลไม่ครบ, การนำเข้า OA · กรองสาขา/ปี · ส่งออก Excel

### 5.12 คลังความรู้ (`/knowledge`)
บทความบัญชี/ภาษีทรัพย์สินสร้างด้วย AI พร้อมแหล่งอ้างอิง (เช่น อายุ/อัตราค่าเสื่อม, เกณฑ์ตั้งทรัพย์สิน, เพดานรถยนต์ 1 ล้าน, TFRS for NPAEs) — เนื้อหา AI ควรให้ผู้สอบบัญชีตรวจก่อนใช้จริง

### 5.13 บันทึกการตรวจสอบ (`/audit`)
ทุกการเปลี่ยนแปลงสำคัญถูกบันทึก แก้/ลบไม่ได้ เก็บ ≥10 ปี กรองตาม action/ผู้ใช้/แหล่ง (UI/OA_SYNC/EXCEL_IMPORT/SYSTEM) · ส่งออก Excel

### 5.14 ตั้งค่า (`/settings`)
8 แท็บ: บริษัท, สาขา, แผนก, ศูนย์ต้นทุน (ข้อมูลหลัก), เลขที่เอกสาร (เลขรันพร้อมพรีวิว), เชื่อมต่อ OA (endpoint/วิธียืนยันตัวตน/โหมด sync/ทดสอบการเชื่อมต่อ), ผู้ใช้งาน, สิทธิ์การใช้งาน (เมทริกซ์ RBAC)

## 6. สถานะทรัพย์สินและรอบค่าเสื่อม

### สถานะทรัพย์สิน (AssetStatus)
| สถานะ | ความหมาย |
|---|---|
| CANDIDATE | รอตรวจสอบ (ยังเป็นรายการ OA/บัญชี ยังไม่เป็นทรัพย์สิน) |
| DRAFT | ฉบับร่าง |
| PENDING_REVIEW | รออนุมัติ |
| ACTIVE | ใช้งาน (คิดค่าเสื่อม) |
| INACTIVE | ไม่ใช้งาน |
| UNDER_REPAIR | ส่งซ่อม |
| TEMPORARILY_UNUSED | พักการใช้งาน |
| DISPOSAL_PENDING | รอจำหน่าย |
| DISPOSED | จำหน่ายแล้ว |
| ARCHIVED | เก็บถาวร |

> สถานะที่ "คิดค่าเสื่อม" ได้: ACTIVE, INACTIVE, UNDER_REPAIR, TEMPORARILY_UNUSED

### สถานะรอบค่าเสื่อม (RunStatus)
`ฉบับร่าง (DRAFT) → คำนวณแล้ว (CALCULATED) → ตรวจแล้ว (REVIEWED) → ปิดงวดแล้ว (LOCKED) → ลงบัญชีแล้ว (POSTED)`
POSTED จะเกิดหลังกด "ส่งเข้าบัญชี ONEBOOK" สำเร็จเท่านั้น

## 7. กฎการคิดค่าเสื่อมและรหัสทรัพย์สิน

### เงื่อนไขทรัพย์สินจะคิดค่าเสื่อมได้ (ครบทั้ง 4 ข้อ)
1. มี **วันที่พร้อมใช้งาน (readyDate)**
2. สถานะ ∈ {ACTIVE, INACTIVE, UNDER_REPAIR, TEMPORARILY_UNUSED}
3. อายุ (lifeMonths) > 0
4. ราคาทุนรวม > มูลค่าซาก

> ทรัพย์สินที่เพิ่งสร้างเป็น DRAFT และ readyDate ว่าง จึงยังไม่คิดค่าเสื่อม ต้องตั้งวันพร้อมใช้ + เปิดใช้งานก่อน

### วิธีคิด
- **เส้นตรง (SL)** ใช้งานได้ (DB/UOP เป็น Phase 2)
- proration: คิดเต็มเดือน / ตามจำนวนวันจริง(÷365) / เริ่มเดือนถัดไป
- งวดสุดท้ายดูดเศษให้ NBV ปิดท้าย = มูลค่าซากพอดี

### รหัสทรัพย์สิน
รูปแบบ `บริษัท-หมวด-ปีYY-ลำดับ` เช่น `SHD-OFE-26-00001` (ลำดับแยกตามบริษัท+หมวด ไม่ใส่สาขาในรหัสเพราะทรัพย์สินย้ายสาขาได้) · เกณฑ์ตั้งทรัพย์สิน = 3,000 บาท/หน่วย

## 8. การเชื่อมต่อกับ ONEBOOK และ One OA

### ONEBOOK → Asset (นำเข้าบิลทรัพย์สิน)
"นำเข้าจากบัญชี" เรียก `/api/onebook/sync` → ดึงบิล (kind bill/expense) ที่ลงบัญชีแล้วและบรรทัดผูกบัญชีสินทรัพย์รหัส 12xx · ทรัพย์สินที่สร้างจะพก `glAccountCode` (เช่น 1240) และ `glCompanyId` ติดไว้

### Asset → ONEBOOK (ส่งค่าเสื่อมกลับ)
ปุ่ม "ส่งเข้าบัญชี ONEBOOK" (หน้าค่าเสื่อม แท็บตรวจสอบก่อนปิดงวด):
- เปิดใช้งานเมื่อ งวด = **ปิดงวดแล้ว** และมีทรัพย์สินที่มี `glAccountCode` + `glCompanyId` และค่าเสื่อมงวดนี้ > 0
- ส่งไป `/api/onebook/post-depreciation` → ONEBOOK ลงสมุดรายวัน **เดบิต 6170 (ค่าเสื่อม) / เครดิต รหัสบัญชีสินทรัพย์+1 (เช่น 1240→1241 ค่าเสื่อมสะสม)**
- กันลงซ้ำงวดเดิม (idempotent) · สำเร็จแล้วงวดเปลี่ยนเป็น "ลงบัญชีแล้ว"

> env ที่ต้องตั้งฝั่ง Asset: `ONEBOOK_BASE_URL`, `ONEBOOK_SYNC_KEY` (ต้องเท่ากับ `ASSET_SYNC_KEY` ฝั่ง ONEBOOK) · ฝั่ง ONEBOOK ต้อง deploy migration `0077` (ฟังก์ชัน `post_external_depreciation`) ด้วย

### One OA → Asset
คำขอซื้อที่อนุมัติใน One OA เข้าคิว "นำเข้าจาก OA" ผ่าน "ดึงข้อมูลจาก OA" (`/api/oa/sync`) และเมื่อสร้างทรัพย์สินแล้วจะยิงกลับแจ้งรหัสทรัพย์สินไปที่ OA (`/api/oa/callback`)

รายละเอียดสถาปัตยกรรม/คีย์ ดู `docs/INTEGRATION.md`

## 9. ภาคผนวก

### คำศัพท์
- **NBV** (Net Book Value) = ราคาทุนรวม − ค่าเสื่อมสะสม (มูลค่าตามบัญชี)
- **readyDate** วันที่พร้อมใช้งาน = จุดเริ่มคิดค่าเสื่อม
- **ค่าเสื่อมสะสม** บัญชีคู่กับบัญชีสินทรัพย์ (รหัสสินทรัพย์+1)

### ข้อควรรู้ Phase 1
- วิธีค่าเสื่อม DB/UOP, ผู้ถือครองทรัพย์สิน, และบางฟีเจอร์ขั้นสูงเป็น Phase 2
- การ Post GL ทำผ่านการเชื่อม ONEBOOK เท่านั้น (หน้าหมวดหมู่ยังขึ้น "Phase 1 ยังไม่ Post GL" สำหรับการลงบัญชีภายใน)

### ไฟล์อ้างอิงสำหรับผู้พัฒนา
- สถานะ/ชนิดข้อมูล: `src/lib/types.ts` · คณิตค่าเสื่อม: `src/lib/depreciation.ts` · สิทธิ์: `src/lib/rbac.ts`
- Store/แอ็กชัน: `src/lib/store.tsx` · ปุ่มส่งค่าเสื่อม: `src/components/post-depreciation-button.tsx`
- เมนู: `src/components/shell.tsx` · i18n: `src/lib/i18n/{th,en,zh}.ts`
