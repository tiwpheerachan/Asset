### 1.3 วงเงินฟอร์มผูกกับยอดรวมตาราง (ประเด็นรีวิว #6) ⭐
- **ปัญหา:** ฟอร์ม "เบิกจ่าย" และ "จัดซื้อ" มีตารางรายการ แต่ช่อง "วงเงิน" (ที่ใช้กำหนดสายอนุมัติ) เป็นช่องกรอกมือแยก → กรอกต่ำหรือเว้นว่างได้ ทำให้วงเงินจริงข้ามขั้นอนุมัติที่ควรผ่าน
- **แก้:** เปลี่ยนช่อง `amount` (role AMOUNT) ของ 2 ฟอร์มนี้เป็นชนิด **TOTAL** รวมจากตารางอัตโนมัติ แก้เองไม่ได้ + เซิร์ฟเวอร์คิดซ้ำกันปลอม
  - REIMBURSE: `sum_of = "expenses.amount"`
  - PURCHASE: `sum_of = "items.qty*unit_price"` (ขยาย `totalOf` ให้บวกผลคูณได้)
- ไฟล์: `lib/form.ts` (totalOf รองรับผลคูณ), `lib/default-forms.json` (override ช่อง amount), `lib/db.ts` (seed override by field_key + เพิ่ม sum_of + migration `amount_autototal` สำหรับ DB เดิม), `app/(app)/admin/forms/[id]/QuestionCard.tsx` (ตัวเลือกผลคูณใน builder)
- ตรวจแล้ว: มีเพียง REIMBURSE/PURCHASE ที่มีตารางเงิน+กำหนดสายด้วยวงเงิน → แก้ครบ ฟอร์มอื่น (DISCOUNT/MARKETING/CREDIT_NOTE) ไม่มีตารางจึงคงเดิม

### 1.4 ฟีเจอร์ "ผู้ดูแลระบบอนุมัติแทน" ⭐ (ใหม่)
- **ความต้องการ:** ให้ผู้ดูแลระบบ (ADMIN) อนุมัติ/ไม่อนุมัติ "แทน" ผู้อนุมัติในสายได้ แม้ไม่ได้อยู่ในสาย
- ระบบมีกลไก on-behalf ผ่านการมอบหมาย (delegation) อยู่แล้ว + บันทึก audit "(อนุมัติแทน X)" → ต่อยอดให้ ADMIN ทำได้โดยไม่ต้องมอบหมายก่อน
- **Backend** (`lib/approval.ts`): ADMIN อนุมัติแทนผู้อนุมัติที่ค้างในขั้นปัจจุบันได้ · บันทึก audit **"อนุมัติแทน … โดยผู้ดูแลระบบ"** · เดินสายต่อตามปกติ ไม่ลัด
- **Backend** (`lib/actions.ts`): ส่ง `approver_row` เลือกทำแทนรายคนได้
- **Frontend** (`app/(app)/requests/[id]/page.tsx`, `components/RequestActions.tsx`): แสดงกล่อง "อนุมัติแทน (ผู้ดูแลระบบ)" + แบนเนอร์เตือน + dropdown เลือกผู้อนุมัติ (ถ้ามีหลายคนในขั้น) · ซ่อน "ถ่ายโอน/เพิ่มผู้อนุมัติ" ในโหมดนี้
- **ปรับตามที่ user ขอเพิ่ม:**
  1. ให้ ADMIN **อนุมัติเอกสารของตัวเองได้** (เดิมบล็อก) — ยกเว้นเฉพาะ ADMIN override, การมอบหมายปกติยังห้าม
  2. พฤติกรรม "ทีละขั้นตามเดิม" (ยืนยันแล้วว่าตรงกับที่ทำอยู่)
- **แก้บั๊ก state ค้างฟอร์ม:** หลังอนุมัติขั้น 1 แล้วกดขั้นถัดไปทันทีขึ้น "ยังไม่ถึงคิว" (ต้องรีโหลด) → แก้ 2 ชั้น:
  - Frontend: คำนวณผู้อนุมัติที่จะทำแทนจากรายการ pending ปัจจุบันทุก render (`effectiveRow`) ถ้ารหัสแถวเก่าไม่อยู่ในขั้นแล้วให้ fallback เป็นคนแรกของขั้นใหม่
  - Backend: ADMIN ถ้า `approver_row` ไม่อยู่ในคิวแล้ว ให้ fallback ไปผู้อนุมัติที่ยังค้างคนแรกของขั้นปัจจุบัน
- i18n: เพิ่มคีย์ `decide.*` (titleAdmin, adminOverride, actForWhom, actingFor, approveFor, confirmApproveFor) ครบ th/en/zh

### 1.5 คำอธิบายกระบวนการ (ไม่มีโค้ด)
- อธิบาย flow การรับเข้าทรัพย์สิน: OA (ขอซื้อ=PR) → อนุมัติตามวงเงิน → APPROVED → ONE Asset ดึงเข้าคิว → จัดหมวด → สร้าง DRAFT → ใส่วันพร้อมใช้+อนุมัติ → ACTIVE → ค่าเสื่อม → ONEBOOK · พร้อมศัพท์ PR/PO/GR/Invoice/GL/capitalize
