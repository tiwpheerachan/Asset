# ส่วนที่ 1 — พื้นฐานที่ทุกคนต้องรู้

## บทที่ 1 — ONEBOOK คืออะไร

ONEBOOK = **สมุดบัญชีหลัก (book of record)** ของกลุ่มบริษัท · ทำเอกสาร **ขาย–ซื้อ รับ–จ่ายเงิน** แล้ว **ลงบัญชีเข้าสมุดรายวันอัตโนมัติ** → ออกงบการเงิน + รายงานภาษี · บริหารสินค้าคงคลัง + หลายบริษัท + ปิดงวด · เป็นเจ้าของ **ผังบัญชี** และเชื่อมกับ **ONE Asset** (ทรัพย์สิน) และ **One OA** (ขออนุมัติ)

**ภาพรวม 1 นาที:**
```
  ทำเอกสาร ──► อนุมัติ/ผ่านรายการ ──► ระบบลงบัญชีให้เอง ──► รับ/จ่ายเงิน ──► งบการเงิน + ภาษี
  (ใบกำกับ/บิล)      (post)          (สมุดรายวัน/แยกประเภท)                    (รายงานจากตัวเลขจริง)
```

> 📌 **แนวคิดหลัก:** คุณแค่ทำ "เอกสารธุรกิจ" ให้ถูก — **ตัวเลขบัญชี (เดบิต/เครดิต) ระบบลงให้เองทั้งหมด** ไม่ต้องกรอกสมุดรายวันมือ

## บทที่ 2 — เข้าสู่ระบบ & หลายบริษัท

1. เข้าที่หน้า Login → อีเมล+รหัสผ่าน **หรือ** ปุ่ม **"เข้าสู่ระบบด้วยระบบกลาง (SSO)"**
2. **สลับบริษัท** ที่มุมบนซ้าย (Company Switcher) — ข้อมูลทั้งหมดแยกตามบริษัทที่เลือก
3. **สลับระบบ** ไป ONE Asset / One OA ได้จากไอคอนบนแถบบน
4. มุมขวาบน = โปรไฟล์ (รูป + ชื่อ + บทบาท)

> 📌 ระบบมีหลายบริษัทในกลุ่ม (เช่น ท็อปวัน, แรบบิท, เอสเอชดี, พีทีซี, แฮชแท็ก, เทราโนวา) · ผู้ที่เห็นข้ามบริษัทได้ต้องมีสิทธิ์ **"ดูบริษัทลูก"** (อ่านอย่างเดียว) หรือเป็น **group admin**

## บทที่ 4 — ศัพท์ที่ต้องเข้าใจก่อน

### 🅐 บทบาท (Role) — มี 7 แบบต่อบริษัท
| บทบาท | ทำอะไรได้ |
|---|---|
| **เจ้าของกิจการ (owner)** | ทุกสิทธิ์ (`*`) |
| **สมุห์บัญชี (accounting_manager)** | สร้าง/แก้/**อนุมัติ+ผ่านรายการ**/ส่งออก, ลงสมุดรายวัน+กลับรายการ, **ปลดล็อกงวด** |
| **พนักงานบัญชี (accountant)** | สร้าง/แก้เอกสาร+สมุดรายวัน **แต่ไม่อนุมัติ/ผ่านรายการ/ปิดงวด** |
| **ฝ่ายขาย (sales)** | เอกสารขาย+ผู้ติดต่อ, ดูสินค้า (ซ่อนราคาทุน) |
| **ฝ่ายจัดซื้อ (purchasing)** | เอกสารฝั่งซื้อ+ผู้ติดต่อ |
| **ผู้บริหาร (executive)** | ดู/ส่งออกได้ทุกอย่าง (อ่านอย่างเดียว) |
| **ผู้ตรวจสอบ (auditor)** | ดู + ดู audit |

**สิทธิ์เป็นคู่ (ทรัพยากร × การกระทำ)** — การกระทำ 10 แบบ: ดู / สร้าง / แก้ / ลบ / **อนุมัติ** / **ผ่านรายการ (post)** / **กลับรายการ (void)** / ส่งออก / **ปลดล็อกงวด** / ข้ามเงื่อนไข
> 📌 **group admin** = ผู้ดูแลสูงสุดของกลุ่ม ข้ามทุกสิทธิ์ทุกบริษัท

### 🅑 สถานะเอกสาร (doc_status)
| สถานะ | ความหมาย |
|---|---|
| **ฉบับร่าง (draft)** | ยังไม่ลงบัญชี แก้ได้ |
| **รออนุมัติ (awaiting_approval)** | เข้าคิวอนุมัติ (ถ้าวงเงินเข้าเกณฑ์) |
| **อนุมัติ/ผ่านรายการ (approved)** | **ลงบัญชีแล้ว** ✅ |
| **รับ/จ่ายบางส่วน (partial)** | ชำระบางส่วน |
| **ชำระครบ (paid)** | รับ/จ่ายครบ |
| **เกินกำหนด (overdue)** | เลยวันครบกำหนดแต่ยังไม่ชำระ |
| **ยกเลิก (void)** | กลับรายการแล้ว (เก็บร่องรอย) |
| **ปิด (closed)** | จบกระบวนการ |

### 🅒 ประเภทเอกสาร (18 แบบ)
**ฝั่งขาย (10):** ใบเสนอราคา, ใบสั่งขาย, ใบส่งของ, ใบวางบิล, ใบแจ้งหนี้, ใบกำกับภาษี, ใบเสร็จรับเงิน, ใบลดหนี้, ใบเพิ่มหนี้, ใบรับเงินมัดจำ
**ฝั่งซื้อ (8):** ใบขอซื้อ, ใบสั่งซื้อ, ใบรับสินค้า, ซื้อสินค้า/บริการ, ค่าใช้จ่าย, ใบลดหนี้ซื้อ, ใบเพิ่มหนี้ซื้อ, ใบจ่ายเงินมัดจำ

## บทที่ 5 — วงจรเอกสาร & การลงบัญชี

```
  (สร้าง) ──► ฉบับร่าง ──[ถ้าวงเงินเข้าเกณฑ์]──► รออนุมัติ ──อนุมัติครบ──┐
                 │                                                      │
                 └──[ไม่ต้องอนุมัติ]──────────────────────────────────►│
                                                                        ▼
                                              อนุมัติ/ผ่านรายการ (ลงบัญชีเข้าสมุดรายวัน)
                                                                        │
                                              รับ/จ่ายเงิน ──► บางส่วน ──► ชำระครบ
                                                                        │
                                              ยกเลิก (void) = สร้างรายการกลับบัญชี (เก็บของเดิม)
```

> ⚠️ **ห้ามบันทึกเอกสารวันที่ที่อยู่ในงวดที่ปิดแล้ว** (จะติด "งวดถูกปิด")
> 💡 เอกสารที่ **ไม่ลงบัญชี**: ใบเสนอราคา, ใบสั่งขาย, ใบขอซื้อ, ใบสั่งซื้อ, ใบวางบิล → แค่เปลี่ยนเป็น "อนุมัติ" ไม่สร้างสมุดรายวัน

# ส่วนที่ 2 — งานขาย (รายรับ)

## บทที่ 6 — สายเอกสารขาย (แปลงต่อเนื่อง)
```
  ใบเสนอราคา ──► ใบสั่งขาย ──► ใบส่งของ ──► ใบแจ้งหนี้/ใบวางบิล ──► ใบกำกับภาษี ──► ใบเสร็จรับเงิน
     (QU)        (SO)        (DO)          (IV/BN)              (TX)          (RE)
                                                                  └──► ใบลดหนี้/ใบเพิ่มหนี้ (CN/DN)
```
- **แปลงเอกสารต่อเนื่อง** = กดจากเอกสารต้นทาง → คัดลอกผู้ติดต่อ+รายการ+อ้างอิงให้อัตโนมัติ (ไม่ต้องพิมพ์ใหม่)
- ⚠️ **ใบส่งของ (DO)** ตัดสต็อก+ลงต้นทุนขายตามวันส่งจริง · พอออกใบกำกับภาษีทีหลังจะ**ไม่ตัดสต็อกซ้ำ** (ลงแค่รายได้)

## บทที่ 7 — สร้างใบแจ้งหนี้/ใบกำกับภาษี 🎯
1. เมนู **รายรับ → ใบกำกับภาษี** → **สร้าง**
2. เลือก **ผู้ติดต่อ (ลูกค้า)** → ที่อยู่/เลขภาษีถูกดึงมาให้ (snapshot ตรึง ณ วันที่เอกสาร)
3. เพิ่ม **รายการสินค้า/บริการ** → ระบบดึงราคา + **คำนวณ VAT 7% ให้อัตโนมัติ** (เลือกแบบแยกนอก/รวมใน/0%/ยกเว้น)
4. ถ้ามี **หัก ณ ที่จ่าย (WHT)** → เลือกประเภท ระบบคิดให้
5. ใส่ **วันครบกำหนด** (เอกสารที่เป็นหนี้ต้องมี) → **บันทึก** (ได้เลขอัตโนมัติ เป็นฉบับร่าง)
6. **อนุมัติ/ผ่านรายการ** → ระบบ **ลงบัญชีให้เอง**

> **ตัวอย่าง:** ขายสินค้า 10,000 + VAT 7% = ชำระ 10,700
> ระบบลงบัญชี: **เดบิต ลูกหนี้ 10,700 / เครดิต รายได้ขาย 10,000 / เครดิต ภาษีขาย 700**

✅ **เช็กลิสต์:** ลูกค้าถูก · เลขภาษีครบ · รายการ+ราคาถูก · VAT ถูกแบบ · วันครบกำหนด

## บทที่ 8 — รับเงิน
- เมนู **การเงิน → รับ–จ่ายเงิน** (ทิศ "รับ") → เลือกใบแจ้งหนี้/ใบกำกับที่จะตัดชำระ (ตัดได้หลายใบ)
- เลือก **ช่องทาง** (เงินสด/ธนาคาร) → ระบบลง **เดบิต เงินสด–ธนาคาร / เครดิต ลูกหนี้** → สถานะเอกสารเป็น "ชำระบางส่วน/ครบ"
- **เงินมัดจำรับ** = หนี้สิน (ยังไม่ใช่รายได้) → ตัดเป็นรายได้เมื่อออกใบกำกับจริง

## บทที่ 9 — ใบลดหนี้ / ใบเพิ่มหนี้
ออกจากใบกำกับภาษีต้นทาง (สินค้าชำรุด/คืน/ปรับราคา) → กลับรายการบางส่วนให้อัตโนมัติ

# ส่วนที่ 3 — งานซื้อ (รายจ่าย)

## บทที่ 10 — สายเอกสารซื้อ
```
  ใบขอซื้อ ──► ใบสั่งซื้อ ──► ใบรับสินค้า ──► ซื้อสินค้า (bill) / ค่าใช้จ่าย (expense)
    (PR)        (PO)         (GR)              (BL/EX)
```
> 💡 ระบบตรวจ **three-way match** (ใบสั่งซื้อ ↔ ใบรับสินค้า ↔ บิล) ก่อนผ่านรายการได้ (ถ้าเปิดใช้)

## บทที่ 11 — บันทึกบิล/ค่าใช้จ่าย 🎯
1. เมนู **รายจ่าย → ซื้อสินค้า** (หรือ **ค่าใช้จ่าย**) → **สร้าง**
2. เลือก **ผู้ขาย** → เพิ่มรายการ → ระบบคิด **ภาษีซื้อ** ให้
3. ถ้าต้อง **หัก ณ ที่จ่าย** → เลือกประเภท (ค่าบริการ 3%, ค่าเช่า 5%, ขนส่ง 1%, โฆษณา 2% ฯลฯ) ระบบหักให้
4. บันทึก → อนุมัติ/ผ่านรายการ → ลงบัญชี

> **ตัวอย่าง:** จ่ายค่าบริการ 5,000 + VAT 350 − หัก ณ ที่จ่าย 3% (150)
> ระบบลง: **เดบิต ค่าใช้จ่าย 5,000 / เดบิต ภาษีซื้อ 350 / เครดิต เจ้าหนี้ 5,200 / เครดิต ภาษีหัก ณ ที่จ่ายค้างนำส่ง 150**

## บทที่ 12 — นำเข้าบิลด้วย AI (OCR) 🎯
เมนู **รายจ่าย → นำเข้าด้วย AI** (`/documents/ai-import`) → อัปโหลดรูป/ไฟล์บิล → AI อ่านผู้ขาย/รายการ/ยอด/VAT ให้ → ตรวจแก้ → บันทึกเป็นเอกสาร (ประหยัดเวลาคีย์)

## บทที่ 13 — จ่ายเงิน
เมนู **การเงิน → รับ–จ่ายเงิน** (ทิศ "จ่าย") → เลือกบิลที่จ่าย → เลือกช่องทาง → ลง **เดบิต เจ้าหนี้ / เครดิต เงินสด–ธนาคาร**

## บทที่ 16 — การลงบัญชีอัตโนมัติ (posting) ★
พอ "อนุมัติ/ผ่านรายการ" ระบบสร้าง **สมุดรายวัน** ให้เอง (เล่ม SALE/PURCHASE, เลข `BOOK-ปีเดือน-ลำดับ`):
| ฝั่ง | เดบิต | เครดิต |
|---|---|---|
| **ขาย** | ลูกหนี้ (ยอดรวม) | รายได้รายบรรทัด + ภาษีขาย · (WHT: เดบิตภาษีถูกหัก / ลดลูกหนี้) |
| **ซื้อ** | ค่าใช้จ่าย/สินค้า + ภาษีซื้อ | เจ้าหนี้ (ยอดรวม) · (WHT: เดบิตเจ้าหนี้ / เครดิตภาษีหักค้างนำส่ง) |
| **สินค้าออก** (ใบส่งของ/ใบกำกับ) | ต้นทุนขาย (FIFO) | สินค้าคงเหลือ |

> 📌 ลงซ้ำไม่ได้ (idempotent) · ตรวจงวดเปิดก่อนลงทุกครั้ง

## บทที่ 17 — สมุดรายวัน / แยกประเภท / รายการปรับปรุง
- **สมุดรายวัน** (`/accounting/journal`) — ดูทุกใบที่ลงบัญชี
- **บัญชีแยกประเภท** (`/accounting/ledger`) — ดูการเคลื่อนไหวรายบัญชี + **drill-down** ย้อนไปเอกสารต้นทาง
- **รายการปรับปรุงด้วยมือ** — ลงเดบิต/เครดิตเองได้ (ต้องบาลานซ์) สำหรับรายการที่ไม่มีเอกสาร

## บทที่ 18 — ปิดงวด & ปิดสิ้นปี
- **ปิดงวด (Freeze)** (`/settings/period-lock`) — ห้ามบันทึก/แก้เอกสารวันที่ ≤ วันปิด (ยกเว้นผู้มีสิทธิ์ปลดล็อก) · เก็บ snapshot ตรวจทานได้
- **ตรวจก่อนปิดงบ** (`/accounting/close-check`) — เช็กลิสต์สิ้นเดือน (ร่างค้าง, ไม่บาลานซ์ ฯลฯ)
- **ปิดบัญชีสิ้นปี** (`/accounting/year-end`) — ล้างรายได้/ค่าใช้จ่ายเข้ากำไรสะสม (เปิดใหม่ได้ถ้าจำเป็น)

# ส่วนที่ 6 — ภาษี (`/tax`)

## บทที่ 19 — ภาษีทั้งหมด
- **VAT 7%** — แบบแยกนอก / รวมใน / 0% / ยกเว้น / ไม่มี · บัญชีภาษีขาย (2140), ภาษีซื้อ (1160)
- **รายงานภาษีขาย/ซื้อ** (`/tax/vat/sales`, `/tax/vat/purchase`) + **ภ.พ.30** (`/tax/pp30`) = ภาษีขาย − ภาษีซื้อ → ยอดต้องชำระ/ยกไป
- **หัก ณ ที่จ่าย (WHT)** (`/tax/wht`) — ตามประมวลรัษฎากร: ค่าบริการ/วิชาชีพ 3%, ค่าเช่า 5%, ขนส่ง 1%, โฆษณา 2%, ดอกเบี้ย 15%, เงินปันผล 10% ฯลฯ · แยก **ภ.ง.ด.3 (บุคคล) / 53 (นิติบุคคล)** อัตโนมัติจากประเภทผู้ติดต่อ · **พิมพ์หนังสือรับรองหัก ณ ที่จ่าย** ได้
- **ภาษีซื้อรอใช้สิทธิ์** (`/tax/pending`) — ใบกำกับที่ยังไม่ถึงเดือนใช้สิทธิ์
- **e-Tax Invoice** (`/tax/etax`) — ใบกำกับภาษีอิเล็กทรอนิกส์

# ส่วนที่ 7 — ผู้ติดต่อ / สินค้า / คลัง

## บทที่ 20 — ข้อมูลหลัก
- **ผู้ติดต่อ** (`/contacts`) — ลูกค้า/ผู้ขาย/ทั้งคู่ · เลขภาษี, **เครดิต (วัน/วงเงิน)**, บัญชีลูกหนี้/เจ้าหนี้ · ระบบ**เตือนเมื่อเกินวงเงินเครดิต** · มีรอบขาย/ใบแจ้งยอด (statement)
- **สินค้า/บริการ** (`/products`) — สินค้า/บริการ/ทรัพย์สิน · ราคาขาย/ทุน, VAT, **ผูกบัญชี GL 4 ตัว** (รายได้/ค่าใช้จ่าย/สินค้าคงเหลือ/ต้นทุนขาย) ← ตัวนี้แหละที่ posting ใช้เลือกบัญชี
- **สินค้าคงคลัง** (`/inventory`) — ต้นทุน **FIFO** · คลังหลายแห่ง, ล็อต/ซีเรียล+วันหมดอายุ, ตรวจนับ, ต้นทุนนำเข้า (landed cost), การจอง

# ส่วนที่ 8 — รายงาน & กลุ่มบริษัท

## บทที่ 21 — รายงาน (`/reports`)
> ทุกตัวอ่านจาก **สมุดรายวันจริง** ไม่มีกรอกมือ
- **การเงิน:** งบทดลอง, งบกำไรขาดทุน, งบแสดงฐานะการเงิน, งบกระแสเงินสด, KPI, เทียบสองงวด
- **ลูกหนี้/เจ้าหนี้:** อายุลูกหนี้ (AR aging), อายุเจ้าหนี้ (AP aging), เฝ้าระวังเครดิต
- **ขาย/วิเคราะห์:** วิเคราะห์ขาย, แยกแผนก, ตามพนักงานขาย, ของค้างส่ง
- ทุกบรรทัด **คลิกดูลึก (drill-down)** ย้อนไปเอกสาร/สมุดรายวันต้นทางได้

## บทที่ 22 — กลุ่มบริษัท (`/group`)
หน้าภาพรวมรวมทุกบริษัทที่เข้าถึงได้: รายรับ/รายจ่าย/กำไร, ลูกหนี้/เจ้าหนี้คงค้าง, เงินสด, สถานะปิดงวด — เห็นภาพรวมทั้งกลุ่มในหน้าเดียว (ต้องมีสิทธิ์ดูรายงาน + ดูบริษัทลูก)

# ส่วนที่ 9 — อนุมัติ / ตั้งค่า / เชื่อมต่อ

## บทที่ 23 — สายอนุมัติ
- ตั้งกฎที่ `/settings/approval` — ต่อ**ประเภทเอกสาร + ช่วงวงเงิน + ลำดับขั้น + บทบาท**
- ถ้าเอกสาร**เข้าเกณฑ์** → สถานะเป็น "รออนุมัติ" → ผู้มีบทบาทนั้นอนุมัติทีละขั้นที่ **คิวอนุมัติ** (`/approvals`) → ครบแล้วจึงผ่านรายการได้
- ⚠️ เทียบจาก **ยอดรวม (grand total)** กันการแตกบิลเลี่ยงเกณฑ์

## บทที่ 24 — ตั้งค่า (`/settings`)
บริษัทในเครือ · ผู้ใช้/สิทธิ์ (บทบาท) · **เลขที่เอกสาร** (prefix/รีเซ็ตรายเดือน-ปี) · มิติ/แผนก (ใช้แยกกำไรขาดทุนตามแผนก) · ปิดงวด · ความปลอดภัย (จำกัด IP, มาส์กคอลัมน์) · ประวัติการใช้งาน (audit)

## บทที่ 25 — เชื่อม ONE Asset
- **ส่งทรัพย์สินให้ Asset:** บิล/ค่าใช้จ่ายที่ผ่านรายการและลงบัญชีสินทรัพย์ (12xx) → ONE Asset ดึงไปขึ้นทะเบียน
- **รับค่าเสื่อมจาก Asset:** ONE Asset ส่งค่าเสื่อมกลับมา → ONEBOOK ลง **เดบิต 6170 ค่าเสื่อม / เครดิต (รหัสสินทรัพย์+1) ค่าเสื่อมสะสม** · 1 ชุดต่อบริษัทต่องวด กันลงซ้ำ
- สลับไปทำงานใน ONE Asset ได้จากไอคอนสลับระบบบนแถบบน

# ส่วนที่ 10 — อ้างอิงเร็ว

## ❓ FAQ
**Q: บันทึกเอกสารแล้วทำไมยังไม่ขึ้นในรายงาน?**
→ ยังเป็น "ฉบับร่าง" — ต้อง **อนุมัติ/ผ่านรายการ** ก่อน รายงานถึงนับ

**Q: ลงวันที่ย้อนหลังไม่ได้?**
→ งวดนั้นถูกปิด (Freeze) แล้ว — ให้สมุห์บัญชี/เจ้าของปลดล็อก หรือลงในงวดที่เปิด

**Q: ต้องกรอกเดบิต/เครดิตเองไหม?**
→ **ไม่ต้อง** — ทำเอกสารให้ถูก ระบบลงบัญชีให้เอง (ยกเว้นรายการปรับปรุงพิเศษ)

**Q: ขายให้ลูกค้าที่เป็นนิติบุคคล หัก ณ ที่จ่ายใช้ ภ.ง.ด. ไหน?**
→ ระบบเลือกให้: นิติบุคคล = ภ.ง.ด.53, บุคคลธรรมดา = ภ.ง.ด.3 (จากประเภทผู้ติดต่อ)

**Q: ยกเลิกเอกสารที่ลงบัญชีไปแล้ว?**
→ ใช้ "ยกเลิก (void)" — ระบบสร้างรายการกลับบัญชีให้ (ไม่ลบของเดิม) ต้องใส่เหตุผล

**Q: เห็นข้อมูลบริษัทอื่นในกลุ่มไม่ได้?**
→ ต้องมีสิทธิ์ "ดูบริษัทลูก" หรือเป็น group admin

## ✅ เช็กลิสต์
**ก่อนบันทึกเอกสาร:** ผู้ติดต่อ+เลขภาษีถูก · รายการ+ราคาถูก · VAT/WHT ถูกประเภท · วันครบกำหนด · วันที่ไม่อยู่ในงวดปิด
**ก่อนปิดงวด:** ไม่มีเอกสารร่างค้าง · กระทบยอดธนาคารแล้ว · ตรวจ close-check ผ่าน

## 📑 ตารางสถานะ (สรุป)
ฉบับร่าง → (รออนุมัติ) → **อนุมัติ/ผ่านรายการ (ลงบัญชี)** → ชำระบางส่วน → ชำระครบ · (เกินกำหนด / ยกเลิก / ปิด)
